# First release implementation and qualification

Source: [issue #20](https://github.com/09millarda/agents-assemble/issues/20). Implementation started from `6e8de86207149efc5d1af99bfce49e7dbdc27e22`, which contained architecture documents and no executable application. The delivered workspace uses TypeScript, Hono, PostgreSQL, React/shadcn, and Zod validation. The foundational subset was committed as `968e49d` after an isolated checkout passed its 21 tests, typecheck, lint, and build. Existing research and `.scratch/` experiments are historical evidence, not qualification of this application.

This record separates executable acceptance paths from external qualification. **The complete first-release journey is not yet qualified.** A passing provider fixture does not establish live GitHub/AWS behavior; an unprivileged supervisor test does not establish the required root-separated Linux installation. A row below identifies a test path and its limits, not a blanket claim that every condition in the story has passed.

- The standalone [reference service](../../examples/reference-delivery) passed its two health tests, build, typecheck, and CloudFormation/SAM lint. The template uses API Gateway and Lambda in `eu-west-1`; the immutable artifact digest is exposed by `/health`.
- The [offline exchange][offline] test passed with two independent fresh PostgreSQL databases, separate installation identities, and local bootstrap. The source was stopped before import and every outbound HTTP request was forbidden; no request was made. Complete bug-fix closure manifests, definitions, and blobs survive export/import/re-export, duplicate import retains its identity, and import creates no execution grant.
- The real backup and restore CLI test passed against disposable PostgreSQL 18.4: identity and immutable content survive; active runs acquire a restore hold; corruption and overwrite attempts are rejected. This does not reconcile an external provider automatically.
- The final Docker image passed a fresh disposable Compose installation with local authentication, administrator bootstrap, project creation, 94 generated OpenAPI paths, static UI, and recent observations from all ten worker contexts. The application role was `aa_control_plane`, with superuser and role inheritance disabled. This installation used no WorkOS or GitHub credentials and performed no cloud deployment.
- `npm run inventory` records both root and reference-example lockfiles, 698 locked dependency entries, and five first-party distribution hashes in [dependencies.json](../distribution/dependencies.json). Actual standalone artifacts retain full upstream texts and the referenced inventory: CLI/control-plane coverage contains 108 installed package/version entries and 34 distinct legal texts; web coverage contains 109 entries and 35 texts, including Vite's emitted runtime. The reference Lambda ZIP contains exact Apache, Hono, and Zod license texts. Re-run inventory and artifact checks after changing a dependency or inventoried input.

The supported action adapter version is `1.0.0`. Deterministic runner adapters are `prepare` and `check`; the deterministic service adapter is read-only `echo`. Service integrations are `publishPR`, `waitMerge`, `staging`, `production`, `verifyHealth`, and `recoverProduction`. Agent labels identify prompts and human labels identify typed requests. Unknown deterministic/integration adapters, incompatible executors, and other adapter versions are rejected by publication/admission validation; they cannot silently select another adapter. The supported environment profile resolves secrets through `local-file` with `refresh_per_attempt`, records the resolver and version evidence for each attempt, and rejects unsupported requested policies at creation and admission.

The supported action profile currently permits one invocation attempt (`retry.maxAttempts: 1`). No automatic invocation retry adapter is qualified. Larger requested retry counts are rejected even when a definition supplies a safe-error label and conformance digest; transport delivery retries and provider reconciliation do not grant another invocation.
