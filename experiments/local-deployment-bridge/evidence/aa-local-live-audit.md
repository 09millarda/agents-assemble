# Independent static audit: local live deployment bridge

Inspected 2026-09-13: `experiments/local-deployment-bridge` in `/tmp/agents-assemble-lambda-deployment`, plus the pending workflow in `/home/amillard98/Documents/git/agents-assemble`. No code execution, implementation edits, AWS calls or external mutations. Findings describe inspected source; they do not attest to a completed live run.

## Actionable gaps before claiming recovery/cutoff guarantees

1. **Mutation permit check is separated from the actual mutation.** `mutationOpen()` precedes provider reads and durable state writes. Those calls can delay past `permit_expires`, yet CreateChangeSet or ExecuteChangeSet is then sent. Recheck immediately before each mutation, and reject an invalid/missing expiry rather than letting `Date.parse` produce NaN. This fixes a concrete local scheduling gap; the account-level four-hour IAM deadline is a different, wider boundary. [provider.mjs](/tmp/agents-assemble-lambda-deployment/experiments/local-deployment-bridge/provider.mjs:40), [execute boundary](/tmp/agents-assemble-lambda-deployment/experiments/local-deployment-bridge/provider.mjs:54).

2. **Automatic restoration has a recoverability gap between registration and claim.** The supervisor commits a rollback effect, then separately claims it. A crash between these operations leaves an approved child; restart unconditionally skips any existing child and will never claim it. Resume an existing approved restoration through the owner, while leaving claimed/terminal children to their normal relay/reconciliation path. Current injected SIGKILL points do not exercise this gap. [drive.mjs](/tmp/agents-assemble-lambda-deployment/experiments/local-deployment-bridge/drive.mjs:26).

3. **Credential exclusion depends on launch environment, not this source.** `common.command` forwards all of `process.env` to owner children. The gateway has no AWS API route and returns no credentials, but nothing in its code removes inherited AWS variables; no gateway-launch wrapper was included in this audit. Start gateway/tunnel with an explicit safe environment and give owner children only PostgreSQL/runtime essentials. A shared local Unix user can still read its AWS configuration or other process-accessible resources: this experiment's host remains trusted, so do not claim process compromise isolation. [common.mjs](/tmp/agents-assemble-lambda-deployment/experiments/local-deployment-bridge/common.mjs:11).

4. **The nominal bounded health sample lacks an explicit request timeout.** `fetch(m.health_url)` has no AbortSignal. A stalled response/body can leave the single supervisor waiting well beyond the intended sample window while ownership remains held. Add an explicit bounded transport timeout and preserve uncertainty on transport errors. A 429 is currently paused, which is safer than treating it as application failure, but the inherited target throttles can cause this at rapid probe rates. [provider.mjs](/tmp/agents-assemble-lambda-deployment/experiments/local-deployment-bridge/provider.mjs:68).

## Remaining evidence/operational limits

- The local supervisor has credentials for both owner databases and writes restoration registrations directly as the trusted Execution test harness. Separate database schemas/roles do not prove security isolation from this supervisor or other trusted local code. Integrations does not directly own approval tables, but the relay is not an independently authenticated network service.
- Operator-created test grants and the controlled contender are not product human approval, build integration or hostile-runner tests. The workflow is pinned to a client commit, while verifier workflow SHA must match the actual dispatch commit; changing main without updating policy should deny.
- Dispatch registration follows GitHub's HTTP acknowledgement, with a fixed ten-second client delay. A lost dispatch acknowledgement or unusually delayed registration can leave a run denied/unregistered. `dispatch.mjs` logs possible dispatch but does not automatically reconcile it; do not claim this live controller proves dispatch lost-ack recovery too.
- Receipt redelivery is explicitly invoked twice to check replay. No actual crash is injected between receipt commit and acknowledgement here. Receipt outcomes trust the Integrations implementation's health/configuration checks; Execution's receipt schema does not independently revalidate all provider configuration fields.
- Paused intents retain ownership but are excluded from the automatic work queue. Unexpected IAM, transport, provider rollback, or timeout errors require explicit reconciliation; only the controlled post-success worker kills automatically resume. Health failure that reaches a valid 503 receipt does invoke automatic restoration.
- Resource cleanup is scoped but not fully restart-idempotent: partial deletion can require manual reconciliation (for example a deleted bucket or role on rerun). Stop provider/supervisor/tunnel before teardown; a policy replacement is not instantaneous revocation of every already accepted AWS operation. Preserve evidence before deletion and independently verify no fixture resources remain.
- Full fixture disappearance, provider outcomes, actual credential redaction and automatic restoration completion must be established from the live evidence. This audit does not upgrade source intent to a conformance result.
