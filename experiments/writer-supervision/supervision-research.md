# Issue #9: Linux native-writer supervision research

Date: 2026-09-12. Research only; no process experiments or repository/issue mutations performed. Local inputs: ADR 0004 and `docs/research/runner-recovery-conformance.md` (Codex CLI 0.153.4 App Server SIGKILL left two identified descendants alive). Primary documentation retrieved today; upstream `main` documents capabilities that must be checked against the deployed versions.

**Conditional recommendation:** use one manager-created transient systemd service and cgroup-v2 subtree per admitted invocation for the Linux reference profile; retain pidfds for exact-process diagnostics. This can support a scoped **contained local processes stopped** observation after measured subtree emptiness and prevented reactivation. It cannot by itself certify that arbitrary malicious same-UID tools, work handed to another daemon, or remote effects stopped. Preserve the ADR's recovery pause wherever ownership, containment, durable identity or evidence continuity is uncertain. Native same-user systemd compatibility still needs an integrated probe.

## What each mechanism establishes

| Mechanism | Supported observation | Limitation |
| --- | --- | --- |
| Parent `wait` / pidfd | The identified process or thread group exited; a held pidfd avoids later PID-reuse confusion. | Descendants can survive. Opening a pidfd for an old numeric PID after restart does not recover the original instance. Obtain at creation or while child-reaping guarantees still hold. [Linux pidfd_open](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) |
| Process-group signal | Signals current group membership. | A child can call `setsid()` and obtain a new session/group; the usual fork/setsid/double-fork pattern also defeats simple ancestry tracking after reparenting. [Linux setsid](https://man7.org/linux/man-pages/man2/setsid.2.html) |
| cgroup-v2 subtree | `cgroup.events` reports `populated 0` only when that cgroup and its descendants contain no live processes. | This describes current members of the subtree, not every process causally originating there or pending external work. [Kernel cgroup-v2](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) |

Cgroup membership is inherited at fork; session changes and reparenting do not themselves migrate a process. `cgroup.kill=1` sends SIGKILL throughout a non-root subtree, handles concurrent forks and protects against migrations during the kill. It is not an enduring admission lock; later external migration/repopulation must be prevented. Wait for `populated 0`; successful kill submission or elapsed timeout is not an exit receipt. Freezing is reversible and allows migration, so `frozen 1` is not terminal stopped evidence. [Kernel cgroup-v2](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)

## Proposed supervision contract (design inference)

1. Journal launch intent and a never-reused unit name derived from an opaque invocation identifier **before** dispatch. Let systemd create the service's initial process in its cgroup; avoid launching the native writer first and subsequently moving its PID into a scope. Services are manager-spawned, while scopes wrap externally created processes. If raw cgroup APIs are selected instead, own a delegated subtree and launch directly into the target cgroup before executable payload work. [systemd delegation](https://systemd.io/CGROUP_DELEGATION/)
2. Use `Type=exec`, `Restart=no`, empty `RestartForceExitStatus`, `KillMode=control-group`, `SendSIGKILL=yes`, `FinalKillSignal=SIGKILL`, explicit finite `TimeoutStopSec`, and no independent activation/restart path. `Type=exec` checks execution of the launcher, not successful native protocol initialization. `ExitType=main` permits cleanup after known launcher loss; `ExitType=cgroup` instead keeps the service running while descendants live and requires an independent bound/stop policy. `RuntimeMaxSec` can provide a supervisor deadline during daemon loss, but grant/deadline mapping remains separate validation. Notify services can extend configured deadlines. [service semantics](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.service.xml), [kill semantics](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.kill.xml)
3. Bind the journal to runner/journal incarnation, assignment/generation/attempt, host kernel boot ID, manager kind/UID, exact unit name, manager-observed `InvocationID`, actual `ControlGroup`, and effective supervision profile. The invocation ID identifies one activation cycle and changes on reactivation. A name, path, PID or a workload-reported environment variable alone is inadequate evidence. [invocation identity](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.exec.xml), [systemd D-Bus properties](https://raw.githubusercontent.com/systemd/systemd/main/man/org.freedesktop.systemd1.xml)
4. On cancel/recovery, inhibit new admission and all local relaunch sources; reconcile the exact manager invocation, request unit stop, await manager state plus subtree emptiness, then durably record the scoped observation before sending it. Use systemd's management API for systemd-owned cgroups; raw `cgroup.kill` belongs only in a subtree the adapter owns through delegation. Do not infer cgroup paths from unit names. Keep the cgroup/unit identity available until terminal evidence is persisted, or retain uncertainty if cleanup races observation. Transient units may be collected when no longer running/referenced, so `unit not found` is not sufficient historical proof. [ownership and ControlGroup lookup](https://systemd.io/CGROUP_DELEGATION/), [transient lifecycle](https://raw.githubusercontent.com/systemd/systemd/main/man/org.freedesktop.systemd1.xml)

## Escape, identity and restart limits

Delegation containment depends on permissions: migration requires write access to the destination and the common ancestor's `cgroup.procs`. An invocation child inside a broader tree writable by the same UID is not automatically an escape boundary. A process that already escaped before killing is outside that subtree's evidence. [Kernel cgroup-v2](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)

The recorded native login works under the customer's existing OS user. Preserve that identity without copying/extracting account credentials, but do not turn it into a security claim. **Inference:** same-user tools with access to the user's service-manager endpoint can ask that manager to create work outside the invocation unit; accessible other daemons provide similar escape paths. Removing one environment variable does not remove those authorities. A privileged system manager, cgroup restrictions, broker restrictions and a stronger sandbox may improve enforcement, but their compatibility with native login and the tool workload is a separate claim. `ProtectControlGroups` has a system-manager-only restriction in current documentation; do not assume it works in a user service. [execution restrictions](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.exec.xml)

Correlate diagnostic PIDs in the observer's PID namespace: a process has different IDs in nested namespaces, and PID-taking syscalls use the caller's namespace. `NSpid` reports the hierarchy; `/proc/PID/stat` start time is measured since boot and is only a correlation aid, not a durable handle. Do not signal a reused numeric PID based on an old journal. [PID namespaces](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html), [NSpid](https://man7.org/linux/man-pages/man5/proc_pid_status.5.html), [start time](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html)

A new kernel boot ID distinguishes kernel instances. **Inference:** a verified reboot of the same enrolled host ends the previous kernel's local processes; daemon restart alone does not. Changed/unknown boot identity invalidates pidfds, process-start timestamps and old cgroup lookups as current handles. Reconcile journal identity, relaunch sources, checkpoint integrity and external effects before any replacement admission; neither a different boot ID from another host nor missing unit metadata proves the intended writer was accounted for. [boot ID](https://raw.githubusercontent.com/systemd/systemd/main/man/sd_id128_get_machine.xml)

The emitted receipt should say `contained_local_processes_stopped`, name its exact scope/profile and preserve external-effect uncertainty. Workspace quiescence also requires accounting for other authorized writers. This research selects a conditional reference mechanism; only actual native stop/reconnect/escape tests can establish an adapter acceptance result.

## Critique of retained-payload observation variant

The proposed `Delegate=yes` service with a trusted supervisor outside an owned `payload/` cgroup solves the measurement race: systemd leaves delegated children to their owner, and an empty payload cgroup remains until explicitly removed. Read `populated 0` on the exact retained payload, commit the observation, then perform unit cleanup. This supports a direct scoped emptiness observation; it does not expand the security boundary. [systemd ownership/delegation](https://systemd.io/CGROUP_DELEGATION/)

Prefer `supervisor/` and `payload/` siblings under the delegated unit, moving the trusted shim into `supervisor/` first. Leaving it in the unit root works only while the relevant no-internal-process constraint is not triggered by enabled domain controllers; sibling groups make the ownership structure explicit. The child may run trusted launcher code to join `payload/` before `exec`, but must perform no native/untrusted work or child creation before migration succeeds. Abort on migration failure. Parent-only later migration reopens the unwanted execution window.

The supervisor must own a one-way launch gate: seal further payload launches/migrations, kill only its owned payload through `cgroup.kill`, await actual zero, durably record the receipt, then remove the payload and stop the unit. Bind the observation to boot ID, unit InvocationID and payload instance, plus ADR assignment identity. A path is not sufficient after deletion/recreation. A held cgroup FD returning ENODEV and missing unit metadata remain unknown unless separately sufficient historical evidence was already committed.

Controller/daemon death must not authorize a new launch. A surviving shim can run the stop-and-journal path independently if its journal ownership/protocol is established; otherwise reconnect preserves uncertainty. A whole-unit stop, manager failure or `RuntimeMaxSec` can kill the shim before the receipt commits. Those are bounded cleanup paths, not guaranteed evidence paths: absent receipt means recovery pause. Allow a finite supervisor-owned payload deadline and time to persist before the manager's outer runtime limit, but do not claim timing guarantees from that margin. Killing only App Server should trigger payload cleanup even when tools outlive App Server. Document whether this behavior is automatic in the shim or explicit in the experiment controller.

The retained sentinel is intentionally still alive while the payload-stop receipt commits. The receipt therefore names the payload writer scope, not the entire unit or host. The trusted shim's journal writes must be distinct from workspace/tool writing. Same-UID processes can still tamper with delegated controls, request work through other available daemons, or act outside the payload; direct zero is conditional on the declared trusted containment profile. This prototype can establish native compatibility and capture actual emptiness without claiming malicious same-UID isolation.
