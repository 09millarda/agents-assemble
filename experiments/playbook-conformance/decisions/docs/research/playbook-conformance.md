# Playbook contract conformance experiment

Date: 2026-09-12. Decision: [#6](https://github.com/09millarda/agents-assemble/issues/6). Map: [#1](https://github.com/09millarda/agents-assemble/issues/1).

## Verdict

**Retain the structured grammar; amend the execution contract with the explicit invariants below.** The feature and bug-fix journeys fit `call`, `sequence`, `choose`, `parallel` with all-join, finite keyed `forEach`, bounded `repeat`, and `end`. This experiment found no need for graph mutation, selective rewind, arbitrary callbacks, or a new node kind. It establishes coherence of a bounded behavioral model, not production conformance of a workflow engine.

The disposable source, single-file interactive walkthrough, fixtures, builder, review and machine-readable results are archived on [codex/prototype-playbook-conformance](https://github.com/09millarda/agents-assemble/tree/codex/prototype-playbook-conformance/experiments/playbook-conformance). From `experiments/playbook-conformance`, run `node run-experiment.cjs` with Node 24; open `playbook-conformance.throwaway.html` directly. `--traces` also writes full JSON snapshots. No packages, accounts, model providers, Git worktrees or real PRs are used by the experiment. The archival Git branch contains the prototype; the main workspace contains decision documents only.

## Experiment and evidence

The actual illustrative YAML definitions were materialized as canonical JSON with explicit bindings, a pinned mock action catalog, a deliberately small JSON Schema profile and explicit finite policies. A local TypeScript builder independently reconstructs the entire feature body and envelope using helpers; it borrows the shared schema/action catalog, not the feature fixture. Node strips its annotations; this is not a TypeScript compiler/typecheck claim. A structured document edit changes the repair limit from 3 to 2 and back. Normalized JSON, node IDs, action pins, policies and ordered arrays match after the round trip. Both starter documents and the fan-out probe pass document round trips; an independent TypeScript builder for the bug journey was not written.

Execution uses a deterministic interpreter and JSON-serializable records. Every invocation consumes a work unit; occurrences include the complete structural and loop/item coordinate, attempts have separate IDs, and publication effects have stable occurrence/slot identities. The mock provider holds delivery mapping and receipts separately from Execution. A restart discards the live state object and reconstructs it from JSON. A mock human command supplies a responder, expected versions and manifest; it is validated before the canonical response can authorize work.

Final automated evidence: **25 authoring probes and 25 runtime scenarios passed; the runtime scenarios contain 89 assertions.** The independent full-feature TypeScript builder and structured edit round trip also passed. Inputs and accepted outputs are validated against the same action catalog during execution. The interactive page was inspected in the browser, including selection of the lost-receipt snapshot, rejection of an unknown behavioral field with raw draft preservation, and a repair-limit edit admitted as a separate run.

## Failures that changed the model and clarify the contract

Independent adversarial review exposed errors in the first model; these were corrected before the final run. They are evidence for making already intended invariants explicit, not reasons to broaden the grammar.

1. **Ordered artifact observation.** Persist artifact identity, source aggregate version and processed-event history independently of the current pending edit. Never order opaque revision IDs lexically. An older/duplicate observation cannot replace a newer proposal or repeat an acknowledged pause; a later source version still requires review. Each production consumer must handle gaps and authoritative head reconciliation under its own inbox protocol.
2. **Complete approval binding.** A schema-shaped `approved` object is insufficient. The effecting context accepts a canonical authorized response for the exact operation, definition/policy and spec, plus the code commit for publication. Implementation validates its scope receipt too. Check/review results carry both the spec reference and checkpoint, and publication admission rejects a mismatch before asking the human.
3. **Explicit recovery reasons.** Retaining a spec does not restart a stopped writer or prove its workspace safe. Pending workspace reconstruction, uncertain effects and cancellation accounting remain distinct obligations. Clearing one must not clear the others. A new invocation requires a proven allowed recovery class and another bounded attempt/work unit.
4. **Budget ownership across lineage.** Package limits cap admission grants; retries and reconstructed invocations spend those grants. A successor requires a new unique run identity and an explicit new admission/grant. Adopting an edit alone cannot reset a run's allowance or silently authorize extra work.
5. **Branch failure is not join completion.** Stop dependent dispatch, request sibling cancellation, preserve outputs and unknown effects, and record recovery until all effects are accounted for. No missing/failed sibling can be treated as a successful all-join.

The fixtures declare two mock-only retry capabilities: `mock_read_transport` on discovery and `mock_verified_reconstruction` on implementation, each with at most two attempts. Other calls have one attempt and no automatic retry. These are simulation assumptions requiring independent adapter proof, not permission to retry real tools.

## Limits and next decision

The state snapshot models one accepted transition at a time. It does not implement PostgreSQL, real process termination, leases/fencing, transactional inbox/outbox, cross-context Human Interaction delivery, or durable timers/backoff/expiry. Authorization, checkpoint reachability and provider receipt lookup are trusted mock boundaries; production tenant/permission enforcement, Git verification, eventual provider visibility and direct-credential failures remain unproven. A first-success receipt always exists in the mock provider; real adapters may have to remain blocked indefinitely when lookup cannot establish an outcome. No throughput, cost enforcement, operating-system, harness-account or live integration claim follows.

The schema profile and editor are deliberately partial. JSON manifests in this model are inspectable snapshots, not a chosen canonical-byte/signing scheme, full SDK, graphical editor or production package-admission implementation. The simulated effect/attempt records are not a substitute for transport redelivery and fault injection at persistence boundaries. The fixed-workflow and observed-edit pause defaults remain amendable architectural defaults, not newly confirmed owner preferences.

The next sharp decision, [#7](https://github.com/09millarda/agents-assemble/issues/7), is to compare durable execution substrates against these traces and prove context-local transaction, inbox/outbox, timer, lease and reconciliation behavior with failure injection. Compare an Execution-owned PostgreSQL state machine with a durable workflow runtime behind a port and a compatible declarative interpreter; eliminate candidates using evidence, not familiarity. Keep the context transaction boundaries from ADR 0001. Release scope and licensing remain #4 and #5; this experiment does not resolve them.
